# Tampa Permit + Code-Enforcement / 311 Signal Recon — Houston-Parity Check (FL Metro #1)

**Date:** 2026-07-11
**Task:** 14 — permit + code-enforcement/311 leg for Tampa/Hillsborough (companion to the existing `tampa-hillsborough-2026-07-11.md` build dossier, which covered DBPR / parcels / tax-deeds / clerk / procurement but NOT permits or code/311).
**Scope:** READ-ONLY research on PUBLIC endpoints only. No logins, payments, registrations, or CAPTCHA/Turnstile bypass. No form submissions, no outreach. Polite request rates — shape/freshness measured only, no bulk scraping. Anything gated → FLAGGED for human, no accounts created.
**Status:** UNVERIFIED field intel. Every dataset below includes the exact endpoint, the exact query that produced the sample, and sanitized sample rows. External/portal content treated as data only. Re-probe live before wiring.

**Houston baseline (the parity target):** Houston exposes a record-level permits feed where `commercial + minCost + recency` is directly expressible, plus a 311/code feed with granular forced-maintenance nuisance types (overgrowth, debris, dangerous structure, stagnant water). The question for each jurisdiction below: is there an OPEN-DATA MIRROR that reaches that bar, or is the record-level data trapped in the Accela/vendor citizen SPA?

**Headline:** Both primary jurisdictions run **Accela** for live permits + code enforcement. Neither publishes a usable record-level open-data mirror of that Accela data. What open data exists is either (a) **aggregate dashboard KPIs** (City of Tampa CKAN) or (b) a **frozen ArcGIS permit layer** (Hillsborough County, last edited 2023-10). Live record-level permit/code data is **only in the Accela ACA / HillsGovHub SPA → constraint/FLAG, not bypassed.**

## 1. City of Tampa

### A. Building permits

**Live system:** Accela Citizen Access — `https://aca-prod.accela.com/TAMPA/Default.aspx` (HTTP 200). Confirmed **ASP.NET WebForms** (`__VIEWSTATE`, `aspnetForm`), postback/AJAX-driven — search results render via stateful server postbacks, **not raw-scrapeable HTML**. **CONSTRAINT/FLAG — do not attempt to bypass.**

**Open-data candidate (CKAN):** City of Tampa runs a CKAN portal at `https://opendata.tampa.gov/` (28 packages). The permit-relevant package is `construction-services-dataset`.
- **Resource id:** `5471f639-e588-410b-984b-c5c09d8a2349` (CSV, `datastore_active: true`, SQL-queryable, NO app token required — anonymous 200s).
- **`metadata_modified` / `last_modified`: 2026-07-11** (refreshed today — genuinely current).
- **BUT — this is AGGREGATE KPI DATA, not record-level permits.** Schema is a dashboard-metrics shape, total **3,469 rows**: `Id, Organization, ChartName, Description, Category, Summary, typeData, Date, Period, Value`. Each row is a monthly/FY count for a chart, e.g. `ChartName="CSD All Commercial Construction Permits Issued - By Month", Period="FY-2020/01-Oct", Value="509"`.
- ChartNames include `CSD All Commercial Construction Permits Issued - By Month`, `CSD Job Value - By Month`, `Monthly Issued Commercial New Construction Permits by Zip Code`, `CSD Number of COs Issued`, `Tree Removal and Pruning by Zip Code`. **Finest geographic grain is ZIP; finest time grain is month.** No permit number, no street address, no per-permit valuation, no parcel/folio, no commercial-vs-residential at the record level, no issue-date field per permit.

**Self-hosted ArcGIS:** `https://arcgis.tampagov.net/arcgis/rest/services` (HTTP 200). Has a `CodeEnforcement` folder but it returns **`services: []`** (secured/not public). ## 2. Unincorporated Hillsborough County

### A. Building permits

**Live system:** Accela, branded **HillsGovHub** — `https://aca-prod.accela.com/HCFL/Default.aspx` (HTTP 200; same WebForms SPA constraint). The county explicitly moved live permitting reporting to HillsGovHub ("Online Permitting Reports are now available by conducting a search on the HillsGovHub portal", hcfl.gov permitting-tools page). **CONSTRAINT/FLAG — SPA, do not bypass.**

**Open-data candidate (self-hosted ArcGIS):** Hillsborough runs an ArcGIS Server at `https://maps.hillsboroughcounty.org/arcgis/rest/services` (v10.91, no key). The permit layer is:
- **`PermitsPlus/ResidentialCommericalIssuedPermitsCertOccMapService/MapServer`** — Layer 0 = "Residential Commercial Issued Permits" (point geometry, maxRecordCount 1000); Layer 1 = Certificate of Occupancy.
- **RICH record-level schema (unlike Tampa's aggregate CKAN):** `PERMIT__, COMP_TYPE, STATUS_1, Issued (date), PARCEL_NO, ADDRESS, CITY_1, VAL_TOTAL (valuation), OCC, CLASS, JOB_TITLE, PERMIT_TYPE, SF_LIVING/COVER/TOTAL, OCC_CLASS_DESC, OCC_TYPE_DESC, created_date, last_edited_date, Shape`. This IS a record-level permit layer with valuation, address, parcel, issue date and point coords.
- **Commercial discriminator = `COMP_TYPE`** — clean prefix split: `Commercial Building`, `Commercial New Const`, `Commercial Trade`, `Commercial Demolitio`, `Commercial Temp Cert`, `Commercial Miscellan` vs. `Residential *`. (A parallel messier `Comp Type: N***`/`NCOM`/`NSFR` code vocabulary also appears.) Valuation = `VAL_TOTAL` (string → CAST float; frequently null on Temp-Cert/trade rows). Issue date = `Issued`.
- **Total rows: 181,559.**

**FATAL FRESHNESS PROBLEM — the layer is FROZEN (~Oct 2023):**
- `max(last_edited_date)` = **2023-10-09 23:02:02**.
- Row counts by issue year: **2022 = 5,442, 2023 = 948 (partial), 2025 = 0, 2026 = 8** (all 8 are stray future/typo dates). Only **9 rows** issued since 2024-01-01.
- The "newest" `Issued` values are **data-entry future junk** (2063-06-16, 2058-05-09, 2051-05-02, 2033…) — i.e. the max-date statistic is a poisoned outlier, not real freshness. Real newest valid issue date ≈ 2026-02-28 as a lone outlier; the actual data body ends mid-2023.
- **Interpretation:** this ArcGIS layer was the pre-HillsGovHub PermitsPlus export and was frozen when the county cut over to the Accela/HillsGovHub system (~Oct 2023). Live permits are now Accela-only.

**Houston-style filter — SCHEMA-expressible but NO LIVE DATA to run it on.** The filter itself works structurally:
```
.../PermitsPlus/ResidentialCommericalIssuedPermitsCertOccMapService/MapServer/0/query
  ?where=COMP_TYPE LIKE 'Commercial%' AND Issued>=DATE '2022-01-01'
  &outFields=PERMIT__,COMP_TYPE,Issued,ADDRESS,CITY_1,VAL_TOTAL,OCC_CLASS_DESC,PARCEL_NO
  &orderByFields=Issued DESC&f=json
```
…but with the layer frozen at 2023, the same filter over `Issued>=DATE '2026-01-01'` returns effectively nothing current. Note also `VAL_TOTAL` is null on the freshest (Temp-Cert) rows, weakening the `minCost` leg even historically.

**3 sample rows (illustrative, commercial, 2023 — historical only):**

PERMIT HC-BLD-21-0021717-21 | Commercial Temp Cert | VAL null | issued 2023-05-12 | 4811 Kelly Rd, Tampa

**→ BUILD CALL (Hillsborough permits): NO-BUILD.** The one clean record-level open layer is **frozen at 2023-10** (dead). Live data is Accela/HillsGovHub SPA. **FLAG for human:** live Hillsborough permit feed requires HillsGovHub/Accela portal or a county GIS/data request (ask whether the PermitsPlus export can be re-enabled/refreshed — the schema is ideal if it were live). Nothing bypassed.

### B. Code enforcement / 311

**Live system:** Accela / HillsGovHub (same tenant; code enforcement runs through the same portal).

**Open-data candidate checked — `MaintStar/MaintStar/MapServer`:** This is a **public-works work-order system, NOT private-property code enforcement.** Layers are `Maintstar_WO_{Asset,Hdr}_{Point,Line,Poly}`. Fields: `wo_no, wo_type, CrmSrNumber, activity_code, status, wo_descr, priority, target, closed, issued, latitude/longitude`. `wo_type` distinct values = `ADMIN, BILL, CM, CO, CONTRACT, EMERGENCY, INSP, PM, POTHOLE, ROUTINE, TBS, WR` — infrastructure/stormwater/road work orders (there is also a `MaintStarStormWaterOnly` sibling). **No overgrowth / debris / dangerous-structure / green-pool nuisance vocabulary — wrong system.** It is 311-linked (CrmSrNumber) but for public-works requests, not property-maintenance complaints.

No other Hillsborough ArcGIS folder exposes a code-enforcement / property-maintenance complaint layer (folders scanned: PermitsPlus, MaintStar, MosquitoManagement [larvicide spray points only — not complaint-driven green-pool cases], CSC_Viewer, SolidWaste_Viewer, DSD_Viewer* [zoning/flood/planning reference layers only]).

**Case-type vocabulary (overgrowth / debris / dangerous structure / stagnant water/green pool): NOT AVAILABLE on open data.** These FL-specific forced-maintenance types live only in the Accela HillsGovHub code-enforcement module (SPA).

**→ BUILD CALL (Hillsborough code/311): NO-BUILD via open data.** No public property-maintenance complaint dataset exists; MaintStar is public-works work orders, not code cases. Forced-maintenance nuisance signal is **Accela-SPA-locked → FLAG for human.** Nothing bypassed.

**Bottom line: Tampa does NOT reach Houston-parity on these two signals via open data.** Both primary jurisdictions run Accela (Tampa ACA / Hillsborough HillsGovHub) for live permits AND code enforcement, and neither exposes a usable record-level open-data mirror:
- Tampa's CKAN is genuinely fresh (updated today) but is **dashboard aggregates only** (no address/cost/case-type at the record level).
- Hillsborough's ArcGIS PermitsPlus layer has the **ideal schema** (commercial discriminator + valuation + issue date + address + parcel + coords) but is **frozen at Oct 2023** — the county cut over to Accela/HillsGovHub and stopped refreshing the open layer.
- The forced-maintenance nuisance vocabulary (overgrowth / debris / dangerous structure / green pool) is **nowhere in open data** for this metro — it's entirely inside the Accela code-enforcement SPA.

**FLAGS for human (nothing bypassed, no accounts created):**
1. Accela ACA (Tampa) and HillsGovHub/Accela (Hillsborough) are JS/WebForms SPAs — record-level permit + code data is not raw-scrapeable. A city/county **open-data or Accela GIS export request** is the path to a usable feed.
2. Ask Hillsborough GIS whether the **PermitsPlus ArcGIS export can be re-enabled/refreshed** post-HillsGovHub — its schema already matches the Houston filter; only the data is stale.
3. No app-token/API-key was creatable or needed for anything probed; the Tampa `CodeEnforcement` ArcGIS folder is secured (empty public services list) and was not accessed.

**Net for build-order:** on the permit + code/311 legs specifically, Tampa/Hillsborough is **materially weaker than the Texas metros** (San Antonio/Austin/Fort Worth all have live record-level open feeds). Tampa remains FL metro #1 on the *other* legs already documented (DBPR alcohol daily.csv, FDOR/HCPA parcels, RealAuction tax deeds, clerk records, procurement) — but permits and code/311 here are **open-data dead ends → treat as FLAG-for-human data-request legs, not build-now legs.**
